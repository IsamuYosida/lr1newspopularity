## Постановка задачи

**Вариант 7 — Online News Popularity (UCI).** Требуется решить задачу регрессии: предсказать количество репостов статьи (`shares`) по её признакам.

Разбиение выполняется по времени с использованием `timedelta`: старые статьи используются для обучения, более новые — для тестирования, имитирующего поток новых публикаций. В этом наборе большее значение `timedelta` соответствует более старой статье; поэтому в обучающую выборку попадают строки с большими значениями, а в тестовую — с меньшими значениями относительно выбранной границы. Такая схема помогает избежать временной утечки.

Модель обучается на `log1p(shares)`, а предсказания преобразуются обратно через `expm1` и ограничиваются снизу нулём. Модель по умолчанию — `HistGradientBoostingRegressor` (`train.model: hist_gb`). В качестве ориентира рассчитывается baseline, предсказывающий константу на основе среднего `log1p(shares)` обучающей выборки.

## Окружение и установка

Требуются Python 3.10 или новее, Git, `uv` и доступ к репозиторию GitHub и DVC-хранилищу в DagsHub.

```bash
git clone https://github.com/IsamuYosida/lr1newspopularity.git
cd lr1newspopularity

# Установить менеджер окружения
python -m pip install uv

# Установить зависимости из зафиксированного lock-файла
uv sync --frozen
```

Если проект запускается не через `uv`, можно экспортировать зафиксированные зависимости и установить их через `pip`:

```bash
uv export --frozen --no-hashes -o requirements.lock.txt
python -m pip install -r requirements.lock.txt
```

## Получение данных

Исходный CSV и артефакты хранятся в DVC remote на DagsHub, а в Git находятся `.dvc`-метафайлы, связывающие файлы с конкретными версиями. Для загрузки нужен DagsHub Personal Access Token.

Настройте доступ к DVC-хранилищу локально:

```bash
dvc remote modify --local origin access_key_id <DAGSHUB_TOKEN>
dvc remote modify --local origin secret_access_key <DAGSHUB_TOKEN>
```

Замените `<DAGSHUB_TOKEN>` своим токеном. Не вставляйте токен в README, код или Git. Команды с `--local` сохраняют настройки в `.dvc/config.local`, который не должен попадать в коммит.

Загрузите данные и доступные DVC-артефакты:

```bash
dvc pull
```

Если при `dvc pull` DVC сообщает, что часть выходных файлов отсутствует в remote, это не мешает пересоздать их через пайплайн, если исходный CSV доступен.

## Запуск пайплайна

Из корня репозитория выполните:

```bash
uv run dvc repro
```

Либо, если зависимости установлены в активное окружение:

```bash
dvc repro
```

DVC выполнит только те стадии, у которых изменились входы, код или параметры. Для принудительного повторного выполнения всех стадий:

```bash
dvc repro --force
```

Посмотреть метрики:

```bash
cat reports/metrics.json
```

Посмотреть граф зависимостей:

```bash
dvc dag
```

## Граф пайплайна

```text
data/external/OnlineNewsPopularity.csv
                  |
                  v
              prepare
                  |
                  v
              featurize
                  |
                  v
                train
                  |
                  v
               evaluate
                  |
                  v
         reports/metrics.json
```

| Стадия | Назначение | Основные результаты |
|---|---|---|
| `prepare` | Проверка схемы и временное разбиение данных | `data/processed/train.csv`, `test.csv` |
| `featurize` | Подготовка матриц признаков и целевой переменной | `data/features/X_train.csv`, `X_test.csv`, `y_train.csv`, `y_test.csv` |
| `train` | Обучение модели на обучающей выборке | `models/model.joblib` |
| `evaluate` | Расчёт метрик модели и baseline, проверка порога `min_r2` | `reports/metrics.json` |

Определение стадий и их зависимостей находится в `dvc.yaml`, параметры — в `params.yaml`, зафиксированные версии зависимостей стадий — в `dvc.lock`.

## Результаты и метрики

Ниже приведены результаты сохранённых прогонов для двух версий данных. Метрики считаются на тестовой выборке, состоящей из более новых статей. MAE и RMSE измеряются в количестве репостов; для них меньшие значения лучше. Для `R²` большее значение лучше.

### Метрики модели

| Версия данных | Всего строк | Строк в тесте | MAE | RMSE | R² |
|---|---:|---:|---:|---:|---:|
| v1 (`data-v1`) | 39 644 | 7 951 | 2087.53 | 8128.65 | 0.0012 |
| v2 (`data-v2`) | 40 644 | 8 106 | 2081.58 | 8089.39 | 0.0012 |

### Baseline

| Версия данных | MAE | RMSE | R² |
|---|---:|---:|---:|
| v1 (`data-v1`) | 2216.37 | 8224.00 | -0.0224 |
| v2 (`data-v2`) | 2215.69 | 8186.54 | -0.0230 |

Модель немного превосходит baseline по MAE и RMSE, однако `R²` близок к нулю. Это означает, что в текущей конфигурации признаки слабо объясняют разброс количества репостов. Числа выше — результаты сохранённых прогонов; при изменении кода, параметров или состава данных метрики могут измениться.

Полный набор скалярных значений, включая число признаков и метрики baseline, записывается в `reports/metrics.json`. Для сравнения метрик двух Git-ревизий можно использовать:

```bash
dvc metrics diff data-v1 data-v2
```

## Смена версии данных

Версии данных связаны с Git-тегами и соответствующими `.dvc`-метафайлами. DVC хранит содержимое данных в своём кэше/remote, а Git фиксирует метаданные и состояние кода.

- **`data-v1`** — исходный датасет UCI, 39 644 строки.
- **`data-v2`** — к исходному набору добавлены 1 000 строк, полученных копированием строк с наибольшим `timedelta` и присвоением им новых значений `timedelta = max_td + 1 + i`. Размер версии — 40 644 строки.

Это искусственное изменение предназначено для демонстрации воспроизводимого переключения версий и пересчёта метрик; оно не является реальным поступлением новых статей. При воспроизведении следует учитывать, что добавленные строки — копии существующих наблюдений с изменённым временным признаком.

### Переключение между версиями

Сначала убедитесь, что рабочее дерево не содержит незакоммиченных изменений. Затем переключитесь на нужный Git-тег и синхронизируйте файлы данных:

```bash
# Перейти к исходной версии
git checkout data-v1
dvc checkout
dvc repro
cat reports/metrics.json

# Перейти к версии v2
git checkout data-v2
dvc checkout
dvc repro
cat reports/metrics.json
```

Чтобы вернуться к основной ветке:

```bash
git checkout main
dvc checkout
dvc repro
```

`git checkout` переключает код и DVC-метафайлы, а `dvc checkout` восстанавливает соответствующие версии файлов данных из локального DVC-кэша. Если нужных объектов нет локально, сначала выполните `dvc pull` при настроенном доступе к remote. Не пропускайте `dvc checkout`: иначе в рабочей папке могут остаться данные от другой версии.

## Что хранится в Git и DVC

- **Git:** исходный код, тесты, конфигурация, `uv.lock`, `dvc.yaml`, `dvc.lock`, `.dvc`-метафайлы и README.
- **DVC remote:** исходный CSV и большие генерируемые артефакты, если они добавлены в DVC.
- **Локально генерируются:** промежуточные данные, модель и отчёт при выполнении пайплайна. `reports/metrics.json` также может фиксироваться в Git для удобного сравнения результатов.
- **Секреты:** токен DagsHub хранится только в локальной конфигурации и не коммитится.
